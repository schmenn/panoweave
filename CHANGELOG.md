# Changelog

## [Unreleased]

### Fixed
- Fine alignment: protected points are no longer moved, re-weighted or dropped (before, a protected point that was not placed by hand got a new position in photo B, and with "drop invalid points" it could be removed). They are still measured: when the spot found in photo B is more than `locked_warn_px` (3 px of the working image) from the point, or no match is found nearby, the status line and the fine-alignment summary say how many and how far, so the person can check them ("only protected" in the point list). A protected control area is kept too.
- Fine alignment with "Add control areas" switched off measured nothing to judge the rounds with, stopped at once and wrote "remaining shift below the threshold – done". It now says that nothing was changed and why.

### Changed
- Build: the Rust version is fixed in `rust-toolchain.toml` (1.99.1, with clippy) for local builds, the CI and the release build, so a new Rust release cannot turn the CI red without a change in the code. It is raised on purpose in its own PR.
- GUI: step 1 shows the photos as a grid that wraps into rows (they ran out of the window to the right before, with no way to scroll). The export step, the connections window and the help window scroll when the window is too low; before, the lower settings could only be reached by making the window bigger. Frame & crop needs no scrolling (the buttons wrap, the preview fits the window). Unit test for the grid columns.
- Code: `cargo clippy --all-targets -- -D warnings` passes and runs in the CI. About 100 warnings fixed (mostly nested `if`s written as one condition); four lints are switched off on purpose in `Cargo.toml` with the reason (many parameters, complex types, index loops, `!(a >= b)` that must fail on NaN). No functional change; all tests unchanged.
- GUI: the last hand-written corner radii (2 to 18 px in the step bar, start-page drop area, point list rows, mask photo list, connection graph, magnifier, patch window) now use `RADIUS` / `RADIUS_CARD`. The big image surfaces (point editor panes, frame preview, mask canvas) are square (`RADIUS_CANVAS` = 0), so a zoomed photo no longer pokes square corners over a rounded edge. Thumbnails in the mask list, the connection window and the seam preview get the same small radius as in the photo list. A unit test fails when a painter call or frame in the UI code gets a written radius again. README screenshots taken again (new tool row, step "Export"). No functional change.

### Added
- Fine alignment settings: "Record patches for this window" (on by default). Off, the patch comparison window is not filled, which saves time and memory; the alignment is the same, and the window says why it is empty. `PW_RECORD=0` switches it off for experiments.
- Points on sky or cloud: new switch "Find points on sky or cloud" (off by default; in the point editor next to "Clean up" and in the list of all points). The sky mask of the photos is made on a worker thread (button "Check N photos", cancelable, kept in memory only, not saved in the project). Every point is checked in both photos with the same cloud score the point finder uses; it counts when the share of sky around it is above the threshold (0.3 to 0.8, default 0.5) in either photo. The list marks these rows blue and has the filter "only those"; "Remove N" removes them as one undo step. Protected points are only marked and never removed; points placed by hand only with "include points placed by hand" (off by default). When nothing can be removed the button says why ("0 to remove (2 by hand, 1 protected)"), and the status line says how many stayed. After the check the toolbar says "sky checked in N photos" (the masks stay in memory, new points are checked at once). Control areas are not judged. Switched off, nothing is computed and nothing is shown. Tried in the GUI by the contributor (before the hand-placed option).
- Point editor: "Snap selected (n)" refines every selected point with the same correlation search as after dragging a point (local zoom/tilt from the other points of the pair, sub-pixel), as a background job with progress and Cancel (nothing is changed when cancelled). The right photo's side of the pair on screen is searched, the left one stays; a result is only taken when the match is at least 80 %. Hand-placed points are snapped too, protected points never. Status line: "n snapped, m unchanged (match too low), k protected skipped". One undo step. If the points change while the job runs, the result is dropped (all) or skipped (single points that were edited meanwhile). Unit-tested (displaced point snaps back, flat area stays, cancel, protected, stale results, one undo step); not tried by clicking through the GUI.
- Point editor: selection shapes as a choice inside "Select / edit" (Click, Rectangle, Lasso, Brush with radius), shown only while "Select / edit" is on. Rectangle and lasso are dragged on empty space (a point under the mouse is still dragged as usual); the brush selects on a single click already and while painting. Plain drag replaces the selection with the points inside; Shift adds; Ctrl takes points out (with the brush, painting adds and Ctrl subtracts). The shape acts on the points of the photo half it was dragged in, for the pair on screen; the right mouse button still moves the photo. Tried in the GUI by the contributor (before the layout change).
- Point editor: multiple selection. Shift or Ctrl+click on a point in either photo adds it to the selection or takes it out again (extra ring around selected points); in the point list (F3) Ctrl+click toggles a row and Shift+click selects the range up to it. "Delete selected (n)" (button and Delete key) removes the whole selection as one undo step. Protected points are never deleted; the message names them. The selection is dropped when the points change in a way that moves their numbers (undo, find, clean up, other photo pair), so it never points at other points. Without Shift/Ctrl everything works as before. Unit-tested; not tried by clicking through the GUI.

## [0.2.0] - 2026-11-07

### Changed
- Documentation: the README lists protected points, duplicate points, undo/redo, the overlap check and the lens correction, and the new modules; `CLAUDE.md` says that notes for later sessions must be written into files at once, that subagents read the project rules first, and that commits and PRs carry no attribution lines.
- Naming: step 5 is now called "Export" everywhere (it was "Save" in the step bar and help, "Create panorama file" on the button, "saved" in messages), so it no longer clashes with "Save project" at the top, which keeps its 💾 icon. The buttons read "Export panorama" and "Export blended picture". Text only, no change in function.
- GUI: one set of style values (`RADIUS` 3 for buttons/fields, `RADIUS_CARD` 6 for cards, tiles, menus and windows, `GAP`, `ROW_H`, `BIG_H` in `consts.rs`) replaces the scattered corner radii (4 to 10), margins and button heights. Rows with many controls (align, frame, export, masks, exposure, start page) now wrap instead of widening the window. No functional change.
- Export: the blend pyramid (building the bands, putting the picture together) uses all CPU cores in the steps that still ran on one. Identical picture. Faster on several cores (single runs varied by about 15 % on the same machine, so no exact figure). `PW_TIMING=1` prints where the time goes (loading, writing, the steps of a strip).
- Export: filling the gaps around the photo edges (`fill_holes`) now uses all CPU cores. The picture is identical pixel by pixel. Faster on several cores (no reliable figure: single runs vary by about 15 %).

### Added
- Lens correction (response curve + vignetting per lens), off by default: new checkbox in the export dialog (Blending, needs "Match brightness and colour"). It solves one exponent per colour channel (tone curve relative to sRGB) and a radial vignetting profile `1 + c1 r^2 + c2 r^4` for every lens from the overlap comparisons of all its photos (robust fit; lenses with fewer than 300 comparisons, implausible results and lenses where nothing is gained get no model, and the log says which and why). The correction is applied per sample in the preview, overlap check, seam finder, brightness factors, gain maps and export (same pixels whatever the strip height). Switched off, no function of it runs and the picture is unchanged (unit test). Measured so far: on the Citadelle project the overlap residuals drop a little (single run), on the Domplatz project not at all, and the telephoto photos look flatter (less contrast) with it. It does not remove the visible sky rectangles. Hence no default-on; the setting is not saved in the project. `PW_LENS=0/1`, `PW_LENS_DEBUG`, `PW_LENS_GAINS=fit` for experiments. Not tried by clicking through the GUI.
- Protected control points: the lock button (key L) in the point editor protects the selected point (lock symbol in the editor and in the point list, filter "only protected"). No bulk action removes or changes a protected point: "Delete all in this pair", Clean up, "Remove outliers" (list and alignment), "Remove N duplicates", deleting from the list, searching a pair again; the status line says how many were kept. Deleting or dragging one point at a time works after unlocking. Locking is one undo step. Old projects load without protected points.
- Control point list: points that lie on top of each other are found and marked (orange rows, hover says which point). Two points of a photo pair on the same spot in both photos are duplicates; the button "Remove N duplicates" removes the worse one of each (hand-placed points stay, nothing is removed without the click). Points that agree in only one photo are marked as contradicting, not removed. Switch and tolerance (default 2 px of the working image) are in the list window, "only those" filters the list.
- Export with little free memory: when not even the smallest strip fits, the photo cache gives up memory first and then the number of blend levels goes down (not below 3). The export dialog says so, the log names the reason. With enough memory nothing changes. `PW_DEMO_TIMEOUT=<seconds>` raises the time limit of the demo runs.
- The export plans with 1.4 times the strip memory it counted before (`StripConfig::memory_factor`): measured on two runs, the program used 1.40 and 1.38 times the planned strip memory (no fixed part), so the old estimate missed temporary copies. This holds on any computer; the budget itself still follows the free memory. The log line of an export now shows the program's memory at the start and its highest value during the export.

### Fixed
- Point editor toolbar: the buttons now sit in fixed rows (find, tools and history, matching parameters, actions, clean up) instead of one long line that broke at random places, so the groups stay together and the vertical spacing between wrapped lines no longer changes with the window width. No change in function. Not tried by resizing the running program.
- Ctrl+Z worked almost nowhere: it was only read in the point editor of the main window, so it did nothing in the point list (F3), the overlap check, the connection view or the patch window, and most changes of the control points had no undo step at all. Now one handler serves the main window and these windows (Ctrl+Z undo, Ctrl+Y or Ctrl+Shift+Z redo, a new change empties the redo list; not while a text field or number box has the keyboard focus, and not while a job is running). Every change of the points is one undo step with a name: delete (point, pair, list, outliers, "Remove N duplicates"), add, move (one step per drag), clean up, find points (all photos or one pair, also the pair re-check) and an alignment that drops outlier points. The Undo button got a Redo partner. Depth is 20 steps (each holds a copy of all points). Steps are forgotten when a photo is removed, all photos are cleared or a project is opened (photo numbers change). Not covered (no undo): crop frame, photo on/off, lens and alignment settings, the connection view settings, the rotations/lenses result of an alignment (Ctrl+Z restores the points and asks to align again). The masks keep their own history, and Ctrl+Z in the mask window only touches the masks. Not tried by clicking through the running program.
- Point editor (step 4): "Add point" and "Patch click" are now one tool choice (like radio buttons) instead of two independent switches. Before, both could light up while a click only did a patch click, and switching patch click off also switched add off. Pressing the active tool again, or Esc, returns to selecting points; "then find more automatically" only shows with "Add point".
- Overlap check: a photo with more pixels per angle than the view (e.g. the 7 mm photos next to 16 mm ones, about 5 times finer) is now averaged down to the view's step before blending/differencing, instead of being point-sampled (aliasing made fine texture show up as a difference). New checkbox "smooth fine photo" (on by default; off = old behaviour). Measured once on the test project (pair 1/2, difference mode): mean difference 0.235 without, 0.209 with the filter; a pair of equal photos gives 0.077.
- Overlap check: the remaining difference between a 7 mm and a 16 mm photo was a different brightness and contrast of the two cameras, not a geometry error. New checkbox "match brightness" (blend and difference mode, on by default; off = plain brightness as before; the checkerboard is never changed): photo B is mapped to the mean and spread of photo A over the common area first. Measured once each on the test project (difference mode, zoom 1): pair 1/2 0.209 -> 0.112, pair 1/3 0.232 -> 0.099, pair 3/4 (equal photos) 0.077 -> 0.075; runs vary by up to about 15 %. What stays red is mostly building edges, where the wide-angle photo is softer. Checks that the view matches the export: a single photo sampled by the view and by the export code (`render_final`, same plane) gave a mean difference of 0.0000 on the test project (photos 1 and 2) and in a unit test, so the view's geometry, gains, gain map and parallax field are the export's. Shifting photo B by up to 1 view pixel (about 0.06 degrees for the 7 mm photo) did not make pair 1/2 fit better, so the "stretched photo" in blend mode is not a geometry error; it is explained by the softness and different contrast of the wide-angle photo (blend now also uses the brightness match). Diagnostics: `PW_OVERLAP_STATS=1`, `PW_OV_TONE=0`.
- Crop frame (step 4): dragging a white edge moved the picture instead of the edge about half of the time (the edge was looked for where the pointer was after the drag threshold, not where it was pressed).

## [0.1.1] - 2026-11-05

### Fixed
- Sporadic crash on Windows (about every fourth start of the export/frame step): wgpu panicked with "Failed to create staging buffer" when Vulkan, DirectX 12 and OpenGL were started side by side. Windows now starts DirectX 12 only; `WGPU_BACKEND` still overrides it. 24 of 24 test runs finished (before: 7 of 27 crashed).

### Added
- Crash report: a panic is written to `%APPDATA%\PanoWeave\crash.log` and the window program shows a message with the file location. The graphics adapter in use is noted in `gpu.log` next to it.

## [0.1.0] - 2026-11-05

First public version.

### Added
- Guided workflow (photos, control points, align, frame and crop, save) with an exposure fusion mode for bracketed shots.
- Automatic control points with a sky/cloud filter, a manual point editor (grow points from a few clicks, patch-click mode that uses the rotation and zoom of nearby points), patch-matching refinement, pair check and a connection graph.
- Memory-independent export: the picture is made strip by strip and streamed to JPEG, PNG, TIFF or BigTIFF; the result does not depend on the available memory. Free disk space is checked first. Target width in pixels, 16-bit TIFF, and cancelling without leaving a partial file.
- Multiband blending with a seam preference for the sharpest photo.
- Smart seams (on by default, can be switched off): a graph-cut seam finder that steers the seams around close objects such as poles and lamps, and that lets a zoomed-in photo win only where there is detail to gain (no coloured patches in the sky).
- Masks: positive/negative masks per photo (brush, lasso, eraser, undo/redo, "Show seams" view, right-click menu on photos) that steer the seams, saved in the project file.
- Smooth brightness correction across each photo (gain maps): evens out sky gradients, vignetting and automatic exposure between photos; option in the export dialog.
- Optional parallax correction near the seams, saved in the project file.
- RAW support as the optional Cargo feature `raw` (on by default; its crates are LGPL licensed). `THIRD_PARTY_LICENSES.md` lists all dependency licenses.
- Secondary windows (patch comparison, mask editor) are real OS windows.
- `--imgdiff` for comparing two pictures and experiment variables for the export and the seams (see the README).
- About 195 unit tests plus end-to-end tests with synthetic images; dual license `MIT OR Apache-2.0`; README screenshots.

### Changed
- `src/app.rs` split into `src/app/` modules (no behaviour change).
- The export always runs strip by strip; `PW_OLD_EXPORT=1` renders the whole picture in memory for comparing.
- Blending is wide ("Automatic") by default.

### Fixed
- With a parallax field, up to 25 visible rows at a photo's top or bottom edge could be cut off in the export.
